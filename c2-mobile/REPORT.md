# C2. Мобильное приложение без опыта

**Вопрос.** К Новому году нужно приложение для iOS, Android и Huawei: банкинг плюс AI-агент. Мобильного опыта у команды нет, есть PWA. Какую технологию взять, что отдать первым, чего не успеть и почему.

**Короткий ответ.** Capacitor поверх существующей PWA. Команда остаётся в своём стеке (TypeScript, React, веб-сборка), а нативные возможности, без которых банк не выпустить, подключаются готовыми плагинами. На стенде путь от PWA до приложения на эмуляторе Android и симуляторе iOS занял 48 минут, включая биометрию, защищённое хранилище и защиту экрана на обеих платформах. Первым выпускаем просмотр (баланс, история) и агента только на чтение. Платежи, push под Huawei и прохождение сторов с финансовым приложением к Новому году - честно «не успеем».

**Huawei.** Здесь два разных мира. Устройства на EMUI и HarmonyOS до 4-й версии запускают Android-приложения, но без Google Play Services. Новые устройства на HarmonyOS NEXT (5 и выше) APK не запускают вовсе, им нужно отдельное приложение на ArkTS/ArkUI. Для первого мира проверил, что сборка от Google-сервисов не зависит: в APK ноль классов `com.google.android.gms` и `com.google.firebase` (`apkanalyzer dex packages`), в манифесте ссылок на них нет. Запуск на образе Android без Google-сервисов: см. раздел «Ограничения».

**Что всплыло по ходу** - это и есть та работа, которой у команды без мобильного опыта не было:
- **Пустой первый кадр.** Холодный старт WebView занимает несколько секунд. Нужен нативный экран загрузки (splash), иначе первое впечатление - белый экран.
- **Нижняя навигация под домашним индикатором iPhone.** `height: 100vh` плюс отступ сверху под safe area без `box-sizing: border-box` делает страницу выше экрана. В браузере это незаметно, на телефоне сразу. Исправлено `box-sizing` (и `100dvh`).
- **Face ID требует строку `NSFaceIDUsageDescription` в `Info.plist`.** Без неё приложение падает при первом вызове. Это требование ревью App Store, а не только техническое.
- **Обновление окружения сломало сборку.** Другой JDK (25 вместо 21) появился в системе и стал выбираться по умолчанию - Gradle перестал собирать. В CI нужно явно закреплять JDK, Xcode и Gradle.
- **Скрипт не нажимает кнопки в симуляторе iOS.** Для автоматической проверки понадобилась отдельная тестовая сборка (`vite build --mode selftest`), которая запускает проверки сама; панель проверок есть только в ней. В проекте нужен UI-тест (XCUITest или Maestro), а не ручные нажатия.
- **Биометрия в плагине - проверка «да/нет», не привязанная к токену.** Токен в хранилище читается и без неё; на устройстве с root или jailbreak такую проверку подменяют (Frida, objection). Для банка нужен ключ, который открывается только биометрией: на iOS - запись Keychain с `SecAccessControl` `.biometryCurrentSet` и `...ThisDeviceOnly` (иначе токен уезжает в зашифрованную резервную копию), на Android - ключ Keystore с `setUserAuthenticationRequired(true)`, который разблокирует `BiometricPrompt` с `CryptoObject`. Взятые плагины этого не делают - это свой небольшой нативный плагин, первая настоящая нативная работа в проекте.

## Решение

**Технология - Capacitor поверх PWA.** Альтернативы:

| Вариант | Почему нет (для этой команды и этого срока) |
|---|---|
| React Native | Логика и знание React/TypeScript переиспользуются, но UI-слой переписывается на нативных примитивах, плюс своя сборка, отладка и экосистема. Для команды без мобильного опыта и срока «к Новому году» - слишком большой объём нового. Хороший кандидат на второй этап, если WebView упрётся в производительность. |
| Flutter | Новый язык (Dart) и новый UI-фреймворк. Код PWA не переиспользуется. |
| Нативно (Swift + Kotlin) | Две новые команды и два кода. К Новому году нереально. |
| Только PWA | Вход по Face ID возможен через WebAuthn/passkeys, но нет Keychain с привязкой к биометрии, защиты экрана, нормальных push на iOS, и в сторах PWA нет. Для банка не вариант. |
| **Capacitor** | Тот же React и та же сборка. Нативная оболочка с плагинами для того, чего нет в вебе. Huawei - тот же APK без Google-сервисов. Риск - производительность сложных экранов в WebView, для банковских экранов просмотра это не критично. |

**Что отдать первым (релиз к Новому году):**
1. Вход: SMS-код и затем биометрия, причём биометрия открывает ключ, а не просто «да/нет» (см. выше); защита экрана с первого кадра; `allowBackup=false`.
2. Просмотр: баланс, история операций, выписка.
3. AI-агент **только на чтение**: отвечает про расходы и операции, ничего не переводит. В спайке ответ на «переведи» - отказ. Права агента ограничены по построению, а не промптом (см. кейс B2).
4. Сборки во все три магазина: App Store, Google Play и AppGallery (тот же APK - для устройств на EMUI и HarmonyOS до 4-й версии).

**Чего не успеем и почему:**
- **Платежи и переводы.** Подтверждение операций, лимиты, антифрод, требования регулятора к подтверждению платежей. Плюс ревью магазинов для приложений с платежами дольше и строже. Это отдельный релиз.
- **Push на Huawei.** Нужен HMS Push Kit: проект в AppGallery Connect (с SHA-256 сертификата подписи), `agconnect-services.json`, HMS Core на устройстве. Официальный плагин push в Capacitor работает только с FCM, для HMS - сторонний или свой плагин; плюс тест на реальном устройстве Huawei. На Android/iOS push - через FCM/APNs.
- **HarmonyOS NEXT.** Новые устройства Huawei не запускают APK: нужно отдельное приложение на ArkTS/ArkUI, по сути третья платформа с нуля. К Новому году - нет; «Huawei» в первом релизе означает AppGallery для устройств на EMUI и HarmonyOS до 4-й версии.
- **Прохождение сторов с финансовым приложением.** Apple и Google требуют, чтобы финансовые приложения публиковал аккаунт организации, нужны документы, политика конфиденциальности, иногда лицензия. Ревью может занять больше недели, а отказ откатывает на ещё одну итерацию. Отдельный риск для обёртки над WebView - правило App Store 4.2 «минимальная функциональность»: приложение должно давать больше, чем сайт (биометрия, push, офлайн). Подавать нужно как можно раньше - этот срок от команды не зависит.
- **Агент с действиями.** Агенту, который может переводить деньги, нужна вся защита из кейса B2: политика вне модели, подтверждение человека, аудит. Это не делается за несколько недель.

## Вывод

Гипотеза подтвердилась: путь «PWA → Capacitor» даёт приложения на обе платформы и Huawei-совместимый APK за час, а нативные требования банка закрываются готовыми плагинами. Главный риск срока - не код, а публикация финансового приложения в трёх магазинах. Её нужно начинать параллельно с разработкой, с первой недели.

## Ограничения

- **48 минут - это время спайка на машине с уже установленными Android SDK и Xcode**, его делал человек с агентом и опытом этих инструментов. Команде без мобильного опыта на первую настройку окружения, подписи и CI стоит заложить дни, а не часы.
- **Сборки debug и симулятор.** Подписи, профилей, релизных сборок и отправки в сторы не было.
- **Проверки на эмуляторе и симуляторе, а не на реальных устройствах.** Биометрия имитирована средствами эмулятора.
- **Huawei:** запуск на образе Android без Google-сервисов не проведён - образ не скачался (обрыв на медленном канале). Вывод о совместимости основан на разборе APK. Сборка под AppGallery и HMS Push не делались.
- **Защита экрана на iOS** подтверждена ответом API и размытием под окном Face ID, без снимка переключателя приложений.
- **Биометрия в спайке не привязана к ключу** (см. «Что всплыло») - это проверка возможности, а не готовая реализация входа.
