> ## Changes
> 
> **New provider**
> - `c1-agent-pr/src/providers/gamma.ts` — `gammaSms(token, baseUrl = 'https://api.gamma-sms.test/v2')`, reusing the existing `HttpSmsProvider` (JSON POST to `/messages`, bearer auth, `Idempotency-Key`), so it behaves identically to alpha/beta.
> 
> **Delivery status**
> - `c1-agent-pr/src/types.ts` — added `DeliveryStatus` (`'delivered' | 'failed'`), `DeliveryState` (`DeliveryStatus | 'pending'`), `DeliveryCallback`, and `DeliveryCallbackError`.
> - `c1-agent-pr/src/delivery.ts` — `DeliveryTracker` maps each `requestId` to the provider message that carried the code and keeps the latest receipt, plus `parseDeliveryCallback()` which validates untrusted webhook bodies.
> - `c1-agent-pr/src/sender.ts` — the sender now records the winning provider/id per `requestId` and exposes:
>   - `handleDeliveryCallback(payload)` — accepts a raw callback body, returns `false` for an unknown message, throws `DeliveryCallbackError` on malformed input;
>   - `deliveryStatus(requestId)` — `'pending'` until a receipt, `'delivered'`/`'failed'` afterwards, `undefined` for a never-sent requestId.
> 
> Receipts are matched by `{ provider, id }` from the send result, so a receipt from a provider that lost a fallback race is ignored. The design also fixes the tracking record if the same `requestId` is sent again after a failure.
> 
> **Tests**
> - `c1-agent-pr/tests/gamma.test.ts` — URL/headers/body of the v2 gateway, retriable 5xx, non-retriable 4xx, network failures, and gamma as the third fallback in the sender chain.
> - `c1-agent-pr/tests/delivery.test.ts` — pending → delivered/failed, latest-receipt-wins, unknown message/provider ignored, lost-fallback receipt ignored, status kept across idempotent `sendCode` calls, no status after total failure, extra callback fields accepted, malformed bodies rejected.
