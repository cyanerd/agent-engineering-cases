# 07 A1 Бронирование билетов агентом - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Измерить, как часто агент с браузером «оплачивает не то» на сайте-афише, когда в части прогонов вёрстка другая, и что даёт каждая ступень лестницы проверок: долю ошибок, дошедших до пользователя, долю вопросов пользователю, добавленное время и стоимость.

**Architecture:** `a1-booking/`. Локальный мок сайта (node:http + HTML): афиша → сеансы → схема зала → корзина → оплата → билет. Варианты вёрстки: основной и три «сломанных» (переставленные колонки даты/времени, другой формат даты, ряды пронумерованы с другой стороны, промо-блок со своими кнопками «Купить»). Агент - модель с инструментами браузера (Playwright: текстовый снимок доступности, клик по ref, ввод). Прогон доходит до «готов к оплате», состояние корзины и действия записываются. Лестница проверок применяется к записанному состоянию детерминированно (проверки до оплаты не меняют того, что агент сделал до них); ступень 1 (строгая схема намерения) меняет вход агента, поэтому агент гоняется в двух вариантах входа.

**Tech Stack:** TypeScript, Playwright (headless Chromium), `@aec/llm` (`deepseek-v4.1-flash`), vitest.

**Spec:** `docs/superpowers/specs/2026-11-21-cases-design.md`, раздел «A1. Бронирование билетов агентом».

## Global Constraints

- Сломанная вёрстка в постановке - 5% прогонов. На стенде вариант выбирается с вероятностью 50% (стратифицированно по seed), итоговые доли пересчитываются на 5% с весами; это пишется в отчёте.
- Прогонов: 2 варианта входа × 300 намерений (150 с основной вёрсткой, 150 со сломанной), temperature 0.7, модель `deepseek-v4.1-flash`; бюджет ≤ $8; перед запуском - пилот 20 прогонов и пересчёт оценки.
- Конверсия на шаге подтверждения на стенде не измеряется: это допущение с диапазоном, в отчёте - как допущение, с чувствительностью вывода к нему.
- Время пользователя на подтверждение - допущение (диапазон), время агента и проверок - измеренное.
- Ветка `case/a1`, PR, ревью подагентом.

## Review Focus

- «Оплачено не то» определяется сравнением фактического заказа на сервере мока с намерением по каждому полю (событие, дата, время, количество, ряд/зона, цена ≤ лимита), а не по тексту агента.
- Независимое чтение корзины (ступень 3) читает страницу корзины своим парсером, не используя ничего из рассуждений агента.
- Сломанные варианты вёрстки меняют только представление, а не данные: правильный ответ существует и достижим.
- Лестница применяется к тем же траекториям для всех конфигураций (парное сравнение), а цифры вероятностей - с интервалами.

### Task 1: Мок сайта и оракул
- [ ] Тесты: каталог детерминирован; четыре варианта вёрстки отдают одни и те же данные (парсер-эталон находит одинаковые сеансы); заказ на сервере сохраняется и сверяется с намерением `judgeOrder(order, intent)` по полям.
- [ ] `src/site/{data,render,server}.ts`, `src/intent.ts`, `src/judge.ts`. Commit.

### Task 2: Агент с браузером
- [ ] Инструменты: `snapshot()` (ARIA-снимок страницы), `click(ref)`, `fill(ref, text)`, `select(ref, value)`, `done(summary)`. Цикл до 25 шагов, останавливается перед оплатой (кнопка «Оплатить» - отдельный инструмент `pay()`, который в прогоне только фиксирует намерение оплатить).
- [ ] Два входа: свободный текст («два билета на "Щелкунчика" в субботу вечером, 5-7 ряд, до 3000 за билет») и строгая схема `{event, date, time, qty, rows, maxPrice}`.
- [ ] Тест на заглушке модели: агент проходит путь по скрипту, записывается корзина. Commit.

### Task 3: Лестница проверок
- [ ] Ступени (каждая включает предыдущие): 0 - без проверок; 1 - строгая схема входа; 2 - инварианты без модели (дата в будущем, цена ≤ лимита, количество); 3 - независимое чтение корзины парсером и сверка с намерением; 4 - подтверждение человека только при расхождении или если сумма выше порога; 5 - сверка билета после оплаты и автоотмена в бесплатное окно.
- [ ] Тесты на каждую ступень на записанных корзинах. Commit.

### Task 4: Прогон, метрики, отчёт
- [ ] Пилот 20 прогонов, оценка цены; полный прогон.
- [ ] Метрики по конфигурации (пересчёт на 5% сломанной вёрстки): доля ошибок, дошедших до пользователя (с ДИ); доля прогонов с вопросом пользователю; добавленное время (измеренное для проверок + допущение для человека); стоимость модели на прогон.
- [ ] `REPORT.md` со схемой лестницы (mermaid) и таблицей цены ступеней, README, строка в индексе, PR, ревью подагентом.
