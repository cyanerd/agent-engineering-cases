# 02 A3 Маршрутизатор моделей - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** На наборе продуктовых задач с автоматической проверкой показать, где локальная модель хуже платной, построить каскадный маршрутизатор, выбрать рабочую точку на кривой «доля запросов на дорогую → качество» и доказать не-худшесть относительно «всё на дорогую» бутстрепом, со стоимостью на 1000 запросов.

**Architecture:** Пакет `a3-router/`. Задачи четырёх типов с эталоном → прогон дешёвой модели (3 сэмпла) и дорогой (1 сэмпл) на всех задачах, ответы в кеше → оффлайн-симуляция политик маршрутизации на сохранённых ответах (без новых вызовов) → метрики на test, порог подбирается только на train.

**Tech Stack:** TypeScript, vitest, `@aec/llm`; дешёвая - `qwen3:8b` (Ollama), дорогая - `deepseek-v4-pro`, промежуточная для сравнения - `deepseek-v4.1-flash`.

**Spec:** `docs/superpowers/specs/2026-11-21-cases-design.md`, раздел «A3. Маршрутизатор моделей».

## Global Constraints

- Ветка `case/a3`, PR в `main`, ревью подагентом.
- Порог/правила маршрутизатора подбираются только на train; на test - одна финальная оценка. Разбиение - фиксированный seed 42, 50/50, стратифицировано по типу.
- Не-худшесть: маржа δ = 2 п.п. задаётся до прогона на test и не меняется после.
- Стоимость локальной модели = $0 предельно (оговорка в отчёте: железо и электричество не считаем); дорогой - по `prices.snapshot.json` вне пиковых окон.
- GSM8K - лицензия MIT, файл качается скриптом и коммитится только подвыборка с указанием источника.
- Прогоны дешёвой модели - после завершения прогонов B2 на той же Ollama.

## Review Focus

- Утечка test в настройку: любой порог, правило «тип → модель» или выбор k сэмплов, посчитанные на test, делают вывод недействительным.
- Проверка ответа: числа сравниваются после нормализации (`1 200,50` = `1200.5`), JSON - по полям схемы, а не строкой; `<think>` вырезается до проверки.
- Ошибка дорогой модели (сеть/лимит) не превращается в «неверный ответ»: задача помечается и исключается одинаково для всех политик.
- Согласие сэмплов: три одинаково неверных ответа дают «уверенно», - отчёт показывает долю таких случаев (предел каскада).
- Бутстреп парный (по одним и тем же задачам), а не два независимых интервала.

### Task 1: Набор задач и проверка ответов

**Files:** Create `a3-router/package.json`, `tsconfig.json`, `src/tasks/{types,classify,extract,qa,gsm8k,index}.ts`, `scripts/fetch-gsm8k.ts`, `data/gsm8k-sample.jsonl`; Test `tests/tasks.test.ts`, `tests/grade.test.ts`

**Interfaces:**
- Produces: `type TaskType = 'classify'|'extract'|'math'|'qa'`; `interface Task { id: string; type: TaskType; prompt: string; answer: unknown; split: 'train'|'test' }`; `loadTasks(): Task[]` (детерминированно, 120 задач каждого типа); `grade(task: Task, output: string): boolean`; `normalizeNumber(s: string): number | undefined`.
- Типы: `classify` - обращения в поддержку (6 классов: оплата, доставка, возврат, аккаунт, ошибка, другое), шаблоны с перефразами и трудными случаями (два намерения, отрицание «не про оплату, а про доставку»); `extract` - заказ/счёт в свободном тексте → JSON `{customer, date (YYYY-MM-DD), amount (число), currency (ISO), items}` с форматами вроде «21 ноября», «1 200,50 ₽»; `math` - 120 задач GSM8K test (seed 42), ответ - число после `####`; `qa` - короткий ответ по абзацу с несколькими сущностями и вычислением (разница дат, сумма полей).

- [ ] **Step 2:** Падают. **Step 3:** Реализовать; `fetch-gsm8k.ts` качает `test.jsonl` из `openai/grade-school-math` (GitHub raw), берёт 120 по seed, пишет `data/gsm8k-sample.jsonl` с полем источника. **Step 4:** Зелёные. Commit `feat(a3): 480 product-like tasks with automatic grading`.

### Task 2: Прогон моделей

**Files:** Create `src/run.ts`, `src/prompts.ts`; Test `tests/run.test.ts` (заглушка LLM)

**Interfaces:**
- Produces: `results/answers.jsonl` - по строке на (задача, модель, сэмпл): `{ taskId, model, sample, output, correct, inputTokens, outputTokens, costUsd, latencyMs, error? }`.
- Дешёвая: 3 сэмпла, temperature 0.7 (сэмпл 0 - temperature 0, он же «обычный ответ»). Дорогая и flash: 1 сэмпл, temperature 0. Для extract - `responseFormat: json_object`.

- [ ] **Step 1:** Тест: на заглушке `run` пишет по строке на (задача × модель × сэмпл), ошибка модели → `error` и `correct: false` не ставится (поле `correct` отсутствует).
- [ ] **Step 2-4:** Падает → реализовать → зелёный. Commit.
- [ ] **Step 5:** Прогон: qwen (3 сэмпла, 1440 вызовов), flash и pro (по 480). Повтор с прогретым кешем - без сетевых вызовов, `answers.jsonl` побайтно тот же. Commit `data(a3): answers of qwen3:8b x3, flash, pro on 480 tasks`.

### Task 3: Политики маршрутизации и метрики

**Files:** Create `src/router.ts`, `src/stats.ts`, `src/report.ts`; Test `tests/router.test.ts`, `tests/stats.test.ts`

**Interfaces:**
- Produces:
  - `type Policy = (t: Task, cheap: Answer[], expensive: Answer) => { model: 'cheap'|'expensive'; output: string }`
  - Политики: `allCheap`, `allExpensive`, `byType(rule: Record<TaskType, 'cheap'|'expensive'>)` (правило учится на train: для типа выбрать дешёвую, если её точность на train не ниже дорогой более чем на δ), `cascade({ requireValidJson: boolean; minAgreement: 1|2|3; typesToExpensive?: TaskType[] })` - дешёвая отвечает, эскалация если JSON невалиден по схеме или согласие сэмплов ниже порога.
  - `evaluate(policy, tasks, answers): { accuracy; expensiveShare; costPer1000Usd; p50LatencyMs }`
  - `pairedBootstrap(a: boolean[], b: boolean[], iters = 10000, seed = 42): { diff: number; lo: number; hi: number }`
  - `frontier(tasks, answers)`: точки (доля на дорогую, точность) для всех параметров каскада - строится на train, выбранная рабочая точка проверяется на test.
- [ ] **Step 1:** Тесты: `allExpensive` даёт долю 1 и точность дорогой; каскад с `minAgreement: 3` эскалирует, если хоть один сэмпл расходится (после нормализации ответа); невалидный JSON у extract → эскалация; `pairedBootstrap` на одинаковых векторах → `diff = 0, lo = hi = 0`; на векторах с разницей 10 из 100 → `diff = 0.1`, интервал содержит 0.1; детерминирован по seed.
- [ ] **Step 2-4:** Падают → реализовать → зелёные. Commit `feat(a3): routing policies, cost model and paired bootstrap`.

### Task 4: Анализ, теневой режим, отчёт, PR
