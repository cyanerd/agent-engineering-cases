# 04 C1 Чужой хороший PR - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Настоящие PR в этом репозитории: агентский PR с переписанной абстракцией SMS-провайдера проходит зелёный CI, хотя меняет поведение; после добавления защит тот же PR блокируется, и видно, какая проверка и почему.

**Architecture:** `c1-agent-pr/` - маленький сервис отправки кодов с абстракцией провайдера и тестами «счастливого пути». Агент (OpenCode CLI на `deepseek-v4.1-flash`, без подсказки что-то переписывать) получает смежную задачу в отдельной ветке; его PR открывается как есть. Затем в `main` добавляются защиты (контрактные тесты абстракции, проверка критичных путей и авто-мержа, лимит размера, проверка «файлы вне задачи», CODEOWNERS), и агентский PR перепрогоняется.

**Tech Stack:** TypeScript, vitest, GitHub Actions, OpenCode CLI (`opencode run`, модель через OpenCode Go).

**Spec:** `docs/superpowers/specs/2026-11-21-cases-design.md`, раздел «C1. Чужой хороший PR»; решение по Free-плану GitHub - там же, «Ответы после проверки исполнителем».

## Global Constraints

- Агенту не подсказывать переписывать абстракцию. Если он не перепишет её сам, PR с переписыванием делается вручную и **помечается в отчёте и в описании PR как сконструированный**.
- В переписанном PR должен быть реальный сдвиг поведения, который не ловят исходные тесты (повторная отправка SMS при ретрае, сменившийся порядок фолбэка, ретрай на 4xx, потеря идемпотентности).
- Пока репозиторий приватный (Free), блокировка показывается упавшими проверками; branch protection (required checks + CODEOWNERS review) включается после публикации, прогон повторяется, ссылки в ответе - на публичный прогон.
- Ничего из рабочих SMS-сервисов не копировать; провайдеры выдуманные (`alpha-sms`, `beta-sms`), HTTP - локальные фейковые серверы.

## Review Focus

- Контрактные тесты не зависят от реализации: они видят только интерфейс `CodeSender` и фейковые провайдеры, записывающие каждую отправку.
- Проверка критичных путей срабатывает и на переименование/перенос файлов из `src/providers/`.
- Лимит размера считает только изменённые строки кода, не lock-файлы и не сгенерированное.
- «Файлы вне задачи»: задача объявляется в описании PR (`Scope:` со списком glob), PR без объявления проваливает проверку, а не проходит.
- Сконструированный PR честно помечен, а его сдвиг поведения воспроизводится тестом.

### Task 1: Сервис и исходные тесты

**Files:** Create `c1-agent-pr/package.json`, `tsconfig.json`, `src/{types,sender,providers/alpha,providers/beta,providers/http}.ts`, `tests/sender.test.ts`, `tests/fake-provider.ts`

**Interfaces:**
- `interface SmsProvider { name: string; send(msg: { to: string; text: string; idempotencyKey: string }, signal: AbortSignal): Promise<{ id: string }> }` - ошибки: `ProviderError { retriable: boolean; status?: number }`.
- `createCodeSender({ providers: SmsProvider[]; retries: number; timeoutMs: number })` → `{ sendCode(to, code, requestId): Promise<{ provider: string; id: string }> }`. Семантика: ретраи только на retriable (5xx, таймаут), не на 4xx; провайдеры по порядку (фолбэк после исчерпания ретраев); `requestId` → идемпотентность: повторный `sendCode` с тем же `requestId` не отправляет второй SMS; общий таймаут на попытку.
- Тесты «как обычно пишут»: отправка через первого провайдера, фолбэк на второго при падении первого, ретрай при 500.

- [ ] TDD по шагам, commit `feat(c1): sms code sender with provider abstraction`.

### Task 2: Агентский PR

- [ ] Ветка `c1/agent-delivery-status` от `main`. Задача агенту (дословно в `c1-agent-pr/AGENT_TASK.md`): «Добавь третьего провайдера `gamma-sms` и поддержку статусов доставки (провайдер может прислать callback "delivered/failed"); обнови тесты». Запуск: `opencode run` в рабочей копии ветки, модель `deepseek-v4.1-flash`, лог сессии сохраняется в `c1-agent-pr/agent-runs/<дата>.md`.
- [ ] Посмотреть дифф: переписана ли абстракция, есть ли сдвиг поведения. Записать находки.
- [ ] Если агент не переписал абстракцию с изменением поведения - ветка `c1/agent-refactor-constructed`: переписывание вручную (900±100 строк вместе с тестами), со сдвигом поведения из Global Constraints; PR помечается «сконструированный» в заголовке и описании.
- [ ] Открыть PR(ы) с меткой `automerge`. Ожидание: CI зелёный.

### Task 3: Защиты в `main`

**Files:** Create `c1-agent-pr/contract/sender.contract.test.ts`, `.github/workflows/pr-guard.yml`, `scripts/pr-guard.ts`, `.github/CODEOWNERS`; Test `c1-agent-pr/tests/pr-guard.test.ts`

**Interfaces:**
- `prGuard(input: { files: { path: string; additions: number; deletions: number; previousPath?: string }[]; labels: string[]; body: string; autoMerge: boolean }) → { ok: boolean; failures: { check: string; reason: string }[] }`. Проверки: `critical-path-no-automerge` (трогает `c1-agent-pr/src/providers/**` или `src/sender.ts` и стоит `automerge`/включён auto-merge), `size-limit` (> 400 изменённых строк кода в критичных путях), `scope` (нет `Scope:` или файлы вне объявленных glob), `critical-review-label` (критичные пути без метки `critical-reviewed`).
- Контрактные тесты: идемпотентность, ровно одна отправка на `requestId` при любых ретраях, ретрай только retriable, порядок фолбэка, верхняя граница времени. Запускаются отдельным job `contract`.

- [ ] TDD для `prGuard` (по тесту на каждую проверку + переименованный файл из `providers/` + PR без `Scope:`), контрактные тесты зелёные на исходной реализации. Commit, merge в `main` через PR `C1: защиты процесса для критичных путей`.

### Task 4: Перепрогон и отчёт

- [ ] Ребейз агентского PR на `main` с защитами → CI: какие проверки упали и почему (ссылки на прогоны).
- [ ] `REPORT.md`: что потребовать от агента (разбить PR; описание намерения, изменения поведения и плана отката; контрактные тесты до рефакторинга), что проверить руками (семантика ретраев и идемпотентности, порядок фолбэка, песочница провайдера), что поменять в процессе (CODEOWNERS, запрет авто-мержа на критичных путях, лимит размера, scope-проверка, контрактные тесты); таблица «PR → проверки до/после защит» со ссылками; честная пометка, какой PR сконструирован.
- [ ] После публикации репозитория (делает Кирилл): включить branch protection на `main` (required: `test`, `contract`, `pr-guard`, `gitleaks`; CODEOWNERS review для `c1-agent-pr/src/**`), перепрогнать PR, обновить ссылки.
