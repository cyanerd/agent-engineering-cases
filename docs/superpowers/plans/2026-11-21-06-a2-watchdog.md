# 06 A2 Ночной watchdog - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** На одной сгенерированной истории прогонов с известной правдой сравнить три механики отделения настоящих поломок от мигания и выбрать одну по цифрам; отпечатки мигания - с живого Playwright-прогона.

**Architecture:** `a2-watchdog/`. Генератор истории (seed): 30 сценариев × 3 прогона в сутки × 4 недели; мигающие сценарии с причинами и отпечатками; эпизоды настоящих поломок с известным началом и концом (в т.ч. «коварные»: поломка с сообщением, похожим на знакомое мигание, и поломка, которая падает не каждый раз). Три детектора читают историю прогон за прогоном (онлайн, без заглядывания вперёд). Оценка - по эпизодам: обнаружено ли, через сколько часов, сколько ложных сигналов, сколько лишних прогонов. Живая часть: игрушечное приложение с гонкой и Playwright-тест, прогнанный N раз, - реальные сообщения об ошибках для отпечатков.

**Tech Stack:** TypeScript, vitest, Playwright (живая часть).

**Spec:** `docs/superpowers/specs/2026-11-21-cases-design.md`, раздел «A2. Ночной watchdog».

## Global Constraints

- Калибровка: базовый «красный на любой сбой» за неделю ≈ 40 сигналов, из них ≈ 30 - мигание (на каждой неделе истории, допуск ±20%); параметры подбираются только по базовому детектору, не по сравниваемым.
- Детекторы онлайн: решение по прогону t использует только прогоны ≤ t (и перепрогоны, которые сам детектор заказал).
- Параметры детекторов подбираются на неделях 1-2 (train), сравнение - на неделях 3-4 (test) и на 20 независимых историях (разные seed) для разброса.
- Ветка `case/a2`, PR, ревью подагентом.

## Review Focus

- Перепрогон в механике 1 видит то же состояние сценария, что исходный прогон (если сценарий сломан - перепрогон тоже падает с вероятностью поломки), а не независимую «монетку» мигания.
- Нормализация отпечатков не склеивает разные ошибки (таймаут на разных шагах) и не разделяет одну ошибку с разными числами/id.
- Эпизод, начавшийся во время карантина сценария, считается пропущенным, если сигнала не было.
- Время до обнаружения считается в часах от начала эпизода до первого сигнала по этому сценарию.
