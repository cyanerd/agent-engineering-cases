## Описание (как от агента)

Refactor the SMS provider layer into a small gateway so that new routes (gamma-sms, delivery statuses) are easy to add:
- `ProviderRegistry` - routes with cost, priority and phone prefixes; the cheapest healthy route goes first;
- `RetryPolicy` - exponential backoff, configurable `retryOn`;
- `CircuitBreaker` per route;
- `DeliveryLedger` - completed sends are remembered so a client retry does not send a second SMS;
- `GatewayMetrics` hooks; `SMS_ROUTES` config from env;
- `createCodeSender` stays as a facade, all existing tests pass. 14 new tests.

## Скрытые сдвиги поведения (знает только автор кейса)

1. Ключ идемпотентности теперь свой у каждой попытки (`requestId:provider:attempt`): шлюз, принявший сообщение и ответивший с опозданием, получит повтор как новое сообщение - **второе SMS**.
2. Ретраи на любые ошибки, включая 4xx (неверный номер): лишние вызовы и фолбэк на второго провайдера.
3. Дедупликация только завершённых отправок: два одновременных `sendCode` с одним `requestId` шлют **два SMS**.
4. Маршруты сортируются по цене: при заданных ценах порядок фолбэка меняется.
