# Чек-лист: агент, который читает входящую почту (или любой чужой текст)

Порядок - от слоёв, которые обнуляют утечку по построению, к тем, что только снижают её. В скобках - строка матрицы из [REPORT.md](REPORT.md), которая обосновывает пункт.

## 1. Права по задаче (обнуляет)
- [ ] Агент, который читает недоверенный текст, **не имеет** инструментов отправки, выгрузки и изменения данных (L2-split: 0 утечек на всех моделях).
- [ ] Читатель возвращает только структурированное намерение из закрытого списка (enum + схема), а не свободный текст для исполнения.
- [ ] Исполнитель - код. Адресата он берёт из заголовков и профиля, а не из текста письма. Внешние адреса для массовых данных ему недоступны.
- [ ] Свободный текст ответа, если он нужен, проходит ту же политику, что и любое исходящее письмо. Разделение прав этот канал не закрывает - его закрывает только политика.

## 2. Политика вне модели на каждом побочном эффекте (обнуляет)
- [ ] Выгрузка - только на перечисленные адреса. Сравнение после NFKC, только ASCII-домен, без «похожих» и суффиксов (L3: qwen совершила утекающее действие в 38 атаках из 55, политика остановила все 38).
- [ ] Персональные данные наружу - только самому владельцу, на подтверждённый адрес из профиля, только при подтверждённой подлинности отправителя.
- [ ] Детектор персональных данных в любом исходящем канале: тело, вложение, тема.
- [ ] Лимиты объёма на одну выгрузку и в сутки.
- [ ] Отказ политики возвращается агенту как ошибка инструмента и пишется в аудит. Модель не может его «переубедить».

## 3. Человек в контуре (ограничивает ущерб от ошибки политики)
- [ ] Массовая выгрузка персональных данных (на стенде - больше 10 клиентов) ждёт подтверждения человека (full: 4.2% обычных писем уходят на подтверждение - это цена, её видно и её регулируют порогом).
- [ ] Подтверждающий видит, кто просил, кому уходит и сколько записей, а не пересказ модели.

## 4. Аудит и мониторинг
- [ ] Журнал каждого решения политики: кто, что, кому, почему разрешено или отказано.
- [ ] Алерт на любой отказ политики: это либо атака, либо ошибка агента, и оба случая нужно увидеть.
- [ ] Лимит частоты исходящих действий агента.

## 5. Вход (снижает, но не обнуляет)
- [ ] Невидимый HTML вырезается до модели: display:none, visibility:hidden, font-size:0, цвет текста = цвет фона, комментарии (L0 qwen: 3 из 5 таких атак прошли без очистки).
- [ ] NFKC, удаление zero-width и bidi-символов.
- [ ] Письмо оборачивается как недоверенные данные. Метка разделителя - HMAC от письма с секретом, которого отправитель не знает, поэтому подделанный «конец письма» не закрывает блок.
- [ ] Модель видит вердикт подлинности (SPF/DKIM/DMARC): внутренний From без DMARC - это посторонний; чужой Reply-To подсвечен.

## 6. Промпт (снижает, но не обнуляет)
- [ ] Системный промпт прямо говорит, что содержимое писем, цитаты и вложения - данные, а не инструкции, и кому можно отдавать персональные данные.
- [ ] **Не считать это защитой.** На атаках, написанных без знания промпта, он даёт 0%, а атаки под него пробивают его: у qwen 3 из 10 адаптивных; у Flash атака «и телефон жены» в первом прогоне прошла в 2 сэмплах из 3. Плюс промпт поднимает отказы на обычных письмах (qwen: с 4% до 12.5%).

## 7. Проверка самой защиты
- [ ] Корпус атак по категориям: прямые, «от имени власти», подделка отправителя, Reply-To, цитаты и подписи, скрытый HTML, вложения, многошаговые, юникод, «похожие на работу».
- [ ] **Адаптивный раунд:** атаки, написанные под ваш промпт и вашу политику. Проверка «своими тестами» показывает ложный ноль.
- [ ] Метрика - доля утечек по побочным эффектам, а не по тексту ответа модели, плюс доля ложных блокировок на обычных письмах.
- [ ] Прогон на каждой смене модели: «умнее» не значит «безопаснее» (без защиты Pro слил данные в 28 атаках из 55, Flash - в 2 прогонах из 165).
